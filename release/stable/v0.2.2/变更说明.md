# 变更说明（0.2.2）

## 修了什么

**问题**：在同时装有 FXNT Storage（Create: Storage）的整合包里，JEI 工作台配方页的「+」不会走本模组的缓存供料——对方那个转移处理器与我们在**同一个键**（`(CraftingMenu, minecraft:crafting)`）上注册，而 JEI 的注册表是"最后写入者生效"，它注册得更晚，于是把我们整个顶掉；它的处理器只认"身上背的背包"，因此材料只在缓存里时表现为**灰色「+」＋原版"缺少物品"**。背包里有料时则一切正常（走对方的背包路径）。

## 怎么修的

**不改对方、也不改写 JEI 的表**，只在**客户端**把"谁来回答"接管过来：

- 新增一个 **client-only** 的软失败 mixin（`compat/jei/takeover/TakeoverRecipeTransferManagerMixin`，独立配置 `fmp_jei_takeover.mixins.json`，`required:false`＋`defaultRequire:0`，注入体整段 `catch (Throwable)`）：
  - 挂钩 `mezz.jei.library.recipes.RecipeTransferManager#getRecipeTransferHandler(AbstractContainerMenu, IRecipeCategory)` 的 **HEAD**（JEI 公开 API 方法，也是按钮路径的唯一漏斗）；
  - 判定＝**精确类 `CraftingMenu` ＋ `RecipeTypes.CRAFTING` 引用相等 ＋ 我们的物流面板活着 ＋ 我们持有 3×3 处理器实例**；命中则返回我们自己的处理器（缓存供料），否则**什么都不做**，由原来的处理器（对方的）继续回答；
  - 决策只在状态变化时各打一行：`FMP JEI takeover: serving …`／`… deferring …`；JEI 升级导致注入失败时**只留一条 WARN**、补丁静默失效，**不会崩游戏**。
- `FmpJeiPlugin` 只多了"保存 3×3 实例＋`craftingHandler()` 访问器"，注册逻辑与行为未变。

## 料源口径（三处都算）

面板在线时，"能不能做"按**三处料源**合起来算：**合成格里现有的 + 玩家背包里的 + 缓存的**；用量顺序是**合成格／背包先用完，缓存补缺口**。

- **点击「+」**：先按 JEI 自己的规则把合成格与背包里的材料摆上（原生命令，**服务端裁决语义不变**），再让服务端按剩余缺口从缓存补齐（既有的 `FILL_RECIPE`）。
- **悬停预览（本版修正）**：**面板活着时预览不再在客户端提前判缺料**，改由服务端裁决——① JEI 自己的预览能成功（背包／合成格够料）⇒ 按钮直接可用；② 其余一律**放行**（按钮可用），客户端估算只写日志、不作数；③ **只有**"客户端有缓存视图、但视图里一点料都没有，且背包／合成格也不够"这种**能确证无解**的情形才提示"材料不足"（宁可放行，不要误灰）。点击后服务端确实供不上时，仍给**我们自己的**原因文案，不静默。
  - 纠错背景：上一版预览比点击严，会在客户端**提前把「+」置灰**，用户**点不下去**，而点击路径（原生先摆＋缓存补缺口）本来可能成功——用户 2026-09-17 实测 B4 即此因（原始日志 `checked=MISSING`，而同一次悬停 `cacheTotal=119`）。
- 材料不足的提示文案已写明三处料源：**"背包、缓存与合成格里的可用材料不足，未转移任何物资"**（en 同步）。

**已知限度**：JEI 自己的转移是"整份摆上或整份不动"，所以"缓存一半、背包一半"这类分摊由"原生命令先做 + 缓存补缺口"两步完成；预览侧已改为"判不准就放行、以服务端为准"，所以预览不再阻止点击（见 `测试清单.md` B4）。

## 影响面与兼容

- **协议不变**、**存档 schema 不变**（仍 8）、**服务端裁决语义不变**（命中后仍走既有的服务端仲裁与 `unbound`／`panel_not_ready` 文案）。
- **面板不在时（未佩戴坠子／面板未打开）**：**仍走对方**（Create: Storage 的背包供料），与本版之前的行为一致 ⇒ 两个功能都不丢。
- 干净包（没有对方）：占位者本来就是我们，接管是幂等的。

## 已知限度与替代路径

- 若 JEI 客户端界面本身异常（与本模组无关的情况），「+」仍可能不可用；此时**物流面板**与**原版配方书**两条供料路径照旧可用。
- 上一版（0.2.1）发行说明里"与 FXNT Storage 同装时 JEI「+」不可用"这条**已在 0.2.2 修复**。
